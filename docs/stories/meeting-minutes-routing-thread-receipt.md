# 保存先選択の即時受付を元スレッドへ返す

利用者として、ワークスペース・プロジェクト・戻るボタンを押した直後の受付も、議事録の元スレッドで確認したい。

## 原因と変更

#988は保存先のやり直しを対象とし、保存先選択に残る認証前の共通受付はresponse_urlのephemeralのままだった。この経路はスレッドを指定していなかった。

- 共通受付は署名とローカル検証を通過した操作に限り、response_urlへin_channel、thread_ts、replace_original:falseを明示する。スレッド参加者にも見える汎用文だけとし、ファイル名・処理ID・利用者・保存先・テナント情報を載せない。
- 認証やキューを待つ前のHTTP 200と短い受付を維持し、処理開始・成功とは扱わない。通知送信待ちが後続処理を止めない。
- 元スレッド座標がない場合は任意の受付を送らず、message.tsやaction_tsへ代替しない。既存の認証済み操作と保存先決定時の永続化済み座標取得は維持する。
- ワークスペース、プロジェクト、戻る、候補変更のボタン値にもsourceThreadTsを引き継ぐ。
- 保存先やり直しは既存の本人限定スレッド通知を維持する。通常の選択画面は元メッセージの更新、生成進捗・結果は既存のスレッド表示を維持する。

## 検証

全ボタンのHTTP即時応答、汎用受付の実HTTP本文、元スレッド欠落・競合時の抑止、ボタン間の座標引継ぎ、既存のやり直し通知を回帰テストする。配備・healthとSlack画面の実表示は分けて報告する。
