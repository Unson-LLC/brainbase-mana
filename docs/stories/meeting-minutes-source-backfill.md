# 議事録の未処理原稿を元スレッドへ安全に戻す

運用担当者として、障害中に取り込まれなかった議事録原稿を、元のSlack投稿を増やさず、同じ処理へ収束させて復旧したい。

## 受入条件

- 管理者は tenant、workspace、channel、元投稿ts、file ID、送信元app IDを完全一致で指定する。
- ManaはSlack履歴から元投稿を読み直し、channel、投稿ts、送信元app、`.txt`添付を照合してから既存の議事録キューへ渡す。
- 処理IDはworkspace、channel、元投稿tsから決定的に生成し、file IDを含む既存のrun ID契約へ接続する。
- 同じ元投稿を再投入しても、保存済みの選択投稿がある場合は新しいSlack返信を作らない。
- 管理トークンに加えて登録済み運用者を使い、Company Authorityから元投稿単位のtenant境界を再発行する。信頼済みの送信元組合せ、tenant境界、Slack履歴のいずれかを確認できない場合は処理せず、失敗段階を返す。
- HTTP受付、キュー投入、保存先選択、生成完了、Slack表示は別の状態として記録・確認する。

## 非対象

- 元のZapier投稿の削除や再投稿
- 保存先の自動決定
- E2E投稿や重複返信の削除

これらは復旧結果の読戻し後に、別の操作として扱う。
