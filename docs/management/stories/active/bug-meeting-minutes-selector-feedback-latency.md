# Story: 議事録の一覧ボタンをすぐ反応させる

## 利用者価値

Slackの議事録保存先を選ぶ利用者として、ワークスペースまたはプロジェクトを押した直後に、押下を受け付けたことを同じメッセージ上で確認したい。これにより、反応がないと誤認して同じボタンを繰り返し押さずに済む。

## 計測結果

- HTTP受付はテナント権限解決を待たずに返る。
- 修正前は、元メッセージの置き換えがテナント権限解決の完了後に直列実行されていた。
- 修正前の認証前表示はスレッドへの汎用返信であり、クリックした一覧メッセージ自体は変化しなかった。
- 遅延を解放しないテナントresolverを使った再現テストでは、修正前は一覧メッセージの更新回数が0のまま待機した。

## 受け入れ条件

- [x] AC-1: ワークスペース選択時は、テナント権限解決が未完了でも同じメッセージを「プロジェクト一覧を開いています…」へ置き換える。
- [x] AC-2: プロジェクト一覧から戻る時は、テナント権限解決が未完了でも同じメッセージを「ワークスペース一覧を開いています…」へ置き換える。
- [x] AC-2b: チャンネル選択時は、テナント権限解決が未完了でも同じメッセージを「処理の開始を確認しています…」へ置き換える。
- [x] AC-3: 認証前表示にrun ID、ファイル名、組織、プロジェクト、チャンネル、利用者、テナントの情報を含めない。
- [x] AC-4: 詳細な一覧表示、テナント認可、受付停止判定、キュー投入の既存境界を変更しない。
- [x] AC-5: 認証前表示の成功時間を構造化ログの `elapsed_ms` で計測できる。
